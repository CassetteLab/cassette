Cassette 1.13.1

FIXED
• When your server refuses something, Cassette now tells you which of the two has a problem. Errors the server reports — a feature it doesn't implement, insufficient permissions, content that's gone, a reply Cassette can't read — all showed up as "Something went wrong", next to a Retry button that replayed the same failing request and failed the same way. The message now says what the server actually answered, and Retry only appears when trying again could change anything.

PLEASE TEST
• Normal use first, non-regression: browse, play, download, search against your own server. Nothing in this release changes what happens when things work — if anything behaves differently from 1.13, that's a bug.
• If you have a second server with an incomplete Subsonic implementation, point Cassette at it and open an artist or an album. You should get a message naming the actual problem, and no Retry button when retrying cannot help.
• Turn your server off mid-session and open an album that isn't downloaded. That one is a connection failure, so the message should talk about reaching the server — and Retry SHOULD be there.
• Internet radio with an unreachable station: the error there used to be raw technical text; it should now read like the rest of the app.
